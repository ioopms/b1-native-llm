# 结果

所有结果都由 `python -m b1 run` / `generate` 产出，目录里保留了当时的候选代码、报告和（生成条件下的）prompt。

| 目录 | 数据集 | 代码来源 | 结果 | 说明 |
|---|---|---|---|---|
| `olive_reference/` | 橄榄油 MIR，4 类 | 仓库内置参考实现（非模型输出） | 32/36 = 88.89% | 测试集饱和：4 条样本 30 种分类器全部判错，其中 3 条疑似标签错误 |
| `raman_reference/` | 拉曼 API 化合物，32 标签 | 仓库内置参考实现（非模型输出） | 97.54% 原始 / 100% 合并同义词 | SNV + 收缩 LDA，约 5 s |
| `raman_generated/` | 同上 | **deepseek-flash 单次生成** | 98.39% 原始 / 99.72% 合并 | 生成 183.9 s、44,116 tokens；执行 6.5 s；3 个错误全是 n-Heptane ↔ n-Hexane |
| `synthetic_generated/` | 合成数据，4 类 | **deepseek-flash 单次生成** | 40/40 = 100% | 端到端自检，生成 101.5 s、19,509 tokens |

## 怎么读

- **`*_reference` 不是模型生成的结果**，是仓库自带的参考程序，用来验证评测链路和给出“一个称职的程序能做到什么”的上界/参照。
- **`*_generated` 是单次生成（B1）的真实模型输出**：一次调用、一次执行、没有任何反馈。
- 拉曼数据集的 32 个标签里有 1 对同义词（MIBK），原始准确率会奖励“利用两个批次的采集差异”，**合并后的指标才是化学上有意义的**。
- 橄榄油数据集的 88.89% 是该测试划分的上限，不是 B1 的能力上限；详见 `data/README.md`。

## 文件

每个目录通常包含：

- `candidate.py`：当时执行的程序（生成条件下就是模型吐出的代码）
- `report.md` / `report.json`：准确率、宏 F1、混淆矩阵、错误样本、一致性检查
- `prompt.txt`：仅生成条件，实际发给模型的完整提示词
